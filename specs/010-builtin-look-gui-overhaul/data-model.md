# Data Model: Built-in Look (GUI Overhaul)

This feature is a presentation change. Stored notes, categories, attachments, sync state, the server protocol and
the database schema are **not** touched (FR-021, SC-009). The only persisted addition is one setting row.

## Persisted: one setting

| Key | Values | Default | Meaning | Validation |
|-----|--------|---------|---------|------------|
| `list_layout` | `list`, `tile` | `list` | The layout the note list was last left in (FR-012a) | `valid_setting` accepts exactly those two values; anything else is refused and the stored value stays |

- Lives in the existing key/value `settings` table, next to `picker_view` (spec 009). No schema version change, no
  migration: a database without the row reads the default, a database with the row opened by an older build ignores it.
- Written when the reader taps the layout toggle; read when the note list is created. Restart-safe (acceptance scenario
  10 of story 2).
- Not synced, not exported, contains no personal data.

Existing settings used by the restyled screens, unchanged: `font_size` (`small`|`medium`|`large`), `sort_order`
(`modified`|`title`), `view`, `rotation`, `sync_after_save`, `picker_view`.

## Transient state (QML only, never stored)

| State | Owner | Lifetime |
|-------|-------|----------|
| Search field open/closed | `NoteListPage` | until the field is closed or the page is left; the search *text* is the existing `bridge.searchText` |
| Which popup (view, sort, menu) is open and its anchor | `NoteListPage`, `EditorPage` | until it is dismissed |
| Bottom panel "text size" open/closed | `ReaderPage` | until closed or the page is left |
| Current page / total pages | the active `ListView`/`GridView`/`Flickable` and `PageButtons` | derived from `contentY`, `height`, `contentHeight` |

## Style constants (`Style.qml`, shipped with the app, not data)

| Group | Members |
|-------|---------|
| Ink | `ink` `#000000`, `hairline` grey, `pressed` light grey, `disabled` mid grey |
| Lines | `hairlineWidth` 1, `ruleWidth` 2, `heavyWidth` 4, `radius` (field 10, dialog 18) |
| Type | `titleSize`, `rowTitleSize`, `bodySize`, `captionSize`, `footerSize`; `uiFamily` (R-5) |
| Geometry | `barHeight`, `rowHeight`, `tileHeight`, `touchMin`, `topInset` (R-9), `gutter` |
| Text size labels | `ptFor(px)` = `round(px × 72 / 300)` (R-7) |

## Entities of the spec, mapped

| Spec entity | Realised as |
|-------------|-------------|
| Look reference | the ten device screenshots (not stored in the repository: they are the reader owner's files); their findings are the table at the top of `spec.md` |
| Application icon | `res/icons/pbnotes.bmp` and `res/icons/pbnotes_f.bmp`, generated by `scripts/make-icons.sh` |
| Style elements | the components in `contracts/ui-components.md` |

## Invariants checked by tests

- Opening, saving, deleting, favoriting, categorizing, syncing and attaching produce the same database rows and the same
  server requests as before the restyle (the existing bridge, store and contract tests pass unchanged).
- `list_layout` round-trips through the store, defaults to `list`, and rejects other values (unit test next to
  `picker_view`).
- The note list in either layout shows the same notes in the same order for the same `view`, `sortOrder` and
  `searchText` (QML test over one fixture).
